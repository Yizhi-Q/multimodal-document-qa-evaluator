# 把项目变成自己能讲清楚的经历

这轮先完成“真实数据 → 模型输出 → 评分 → 错误分析”的实验流程。运行后亲自做下面三件事：

1. 打开验证集中的五张票据，对照原图、标准答案和模型输出，解释每个错误发生在哪里。
2. 选一种常见错误，只改一个地方，例如提示词、图像像素上限或数字评分规则。先说明预计改善什么，再跑同一验证集。
3. 记录失败的尝试。说明哪些结果支持判断，哪些仍不确定，再冻结配置跑测试集。

面试前应能回答：

- 为什么需要 JSON 解析和字段 Schema？模型不按格式回答时怎么办？
- 为什么 3 张合成样例的 100% 分数不能证明模型能力？
- 验证集与测试集有什么区别？哪些参数在验证集上选的？
- CORD 没有标注某字段，为什么不直接算模型“幻觉”？
- 4-bit 量化、输入分辨率、输出长度分别如何影响显存与效果？
- 为什么失败请求也要计入分母？字段准确率与整单准确率有何区别？
- 哪些代码由 AI 协助实现？哪些设计、排错、实验和改进是你亲自理解并完成的？

真实跑通后，简历写清数据规模、任务范围、配置、实测结果和个人贡献。未跑通前只描述已实现的功能。
