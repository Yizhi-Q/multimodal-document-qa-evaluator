# 票据错误改进实验

## 改动依据

本轮只根据已使用的 CORD 验证集前 20 张及其原图复核设计改动：

- `cord-validation-0001`：模型把 `Tunai` 旁的付款金额当成 `Total`。
- `cord-validation-0002`：模型把页脚税率 `10%` 当成税额，并把总额当作现金支付金额。
- `cord-validation-0017`：模型改变金额分隔符并添加零。该图也存在官方标注与可见文本不一致的问题，继续保留原标注及评分。

原图、旧输出与人工判断见 [验证集复核](VALIDATION_REVIEW.md)。本轮没有根据已经发布的测试集错误挑选提示词。

## 已实现的改动

### 可切换的提取规则

`MLLM_RECEIPT_PROFILE=baseline` 保留原来的提取提示。`label-aware-v1` 增加：

- 六类金额的标签与含义，明确 `Total`、`Cash/Tunai`、`Change/Kembali` 的对应关系。
- 税额、服务费须为印刷金额；仅有百分比时返回 null，不能通过算式生成金额。
- 逐字保留数字、逗号、点、货币前缀与印刷零；禁止自动重排金额格式。
- 要求简短转录标签及其金额，供人工复核。模型生成的 evidence 仍未经过独立验证。

新规则仅适用于 `string or null` 的票据金额字段。默认仍为 baseline；新规则是否有效以真实对照结果为准。

首轮长规则在同一批 20 张上由 54/72 降到 52/72，平均耗时由 2.236 秒增至 6.881 秒，因此未进入留出验证。其五个字段由错变对、七个字段由对变错，逐条结果保留。税额与总额的部分修正不足以证明整体改进。

第二个候选 `receipt-compact-v1` 缩短标签规则，并将模型输出限制为 `fields` 对象，减少重复解释与 evidence 的生成。它是另一套提取协议，效果与时间要重新运行确认。解析器仍提供兼容的结果结构，其中空 evidence / 默认 confidence 不代表已验证或校准。

该候选实际得到 49/72（68.06%），比 baseline 更差，因此也未进入留出验证。部分票据丢失 `Rp` 前缀；另有模型返回 `requested_field` 示例键的情况。本轮新增解析检查，将没有任何所请求字段名的非空 fields 对象识别为解析失败；旧原始记录与其旧解析结果继续保留。

### 输出复核提示

`review_flags` 与 `review-flags.csv` 标记金额字段中的百分比、错误的数据类型、占位字符串或没有数字的文本。检查只读取预测，不访问标准答案，不替换原预测、不删除标点、不改评分。

这些提示不能发现所有读错的数字、分隔符或字段。没有提示不代表提取正确；null 也不代表已经验证票据上没有该字段。

### 仅复核明确异常的金额

第三个候选 `amount-recheck-v1` 使用原 baseline 提取规则。仅当 `review_flags` 检出百分比、错误类型或占位文本时，追加一次读取原图的请求，且只请求被标记的字段，不向模型传入标准答案或建议金额。

第二次输出通过同样的格式检查后，替换相应字段；其他字段保留初次输出。失败或仍存在格式异常时保留原值。记录保留 `initial_prediction`、`recheck_attempt`、两个原始响应、额外请求耗时及失败原因。整张耗时包括复核；两次请求的已记录生成耗时求和，显存取两次最大值。若第二次请求失败，无法完整测量的生成指标留空。

复核增加请求成本，不能保证新金额正确，也不能修复未被格式检查发现的错位或错误数字。本轮在开发样本上验证后再决定是否冻结用于留出验证。

该整图、单字段复核在前 20 张仍为 54/72（75.00%），没有增加正确标注字段。另一个 `percent-crop-v1` 只对百分比使用票据中部 80% 高度的局部图，保留全宽、记录裁剪位置和图片校验值；局部图返回 null 时不能据此判断整张票据缺失字段。该方案同样为 54/72，也未选为最终候选。

### 最终候选：保留上下文，只合并异常字段

`MLLM_RECEIPT_RECHECK=label-context-v1` 保留 baseline 的初次提取。仅在金额返回百分比时，使用原图、原问题和完整 Schema，追加一次 `label-aware-v1` 提取。这样保留周围金额和标签的上下文；只合并被百分比检查标记的字段，其他字段全部保留初次输出。

前 20 张实测从 54/72 提升到 55/72（75.00% → 76.39%），修正一个税额字段，没有新增字段错误。`cord-validation-0002` 的税额由 `10%` 改为 `1,818`；该张原有的现金支付金额错误仍存在。整单准确率仍为 50%，不能把一个字段的修正写成整张票据已正确。

合并结果的证据只替换被采纳字段的条目；清空初次解释与合并结果的 confidence，避免沿用与新字段不一致的信息。初次解释、confidence 及全部响应继续保留在复核记录中。金额缺少货币前缀、分隔符错误或取错字段仍可能不触发该复核。

留出验证前冻结这套规则。最后一次修改仅处理合并结果中的旧证据、解释和 confidence，未更改模型输入、金额预测或评分；开发对照与留出对照分别记录源代码哈希，各自的新旧方案使用同一版本。

## 留出验证结果与选择

随后一次性运行此前未参与调参的 80 张验证票据，共 281 个标注字段：

| 方案 | 正确字段 | 字段准确率 | 整单准确率 | 文档失败 / 复核失败 | 平均每张秒数 |
|---|---:|---:|---:|---:|---:|
| baseline，不额外复核 | 227/281 | 80.78% | 65.00% | 0 / 0 | 2.338 |
| baseline + label-context-v1 | 227/281 | 80.78% | 65.00% | 0 / 0 | 2.321 |

只触发了一次百分比复核，该次输出仍未通过金额格式检查，所以保留原值。所有被评分字段与 baseline 一致，改善和退步均为 0。单次运行的微小耗时差异不能说明加速。

**没有观察到留出集准确率提升，因此默认仍为 `MLLM_RECEIPT_PROFILE=baseline`、`MLLM_RECEIPT_RECHECK=none`。** 复核方案作为可复现实验保留，不能把开发集的一个字段修正当作普遍改进，也不替换原测试成绩。这 80 张现已使用；后续调参后需要另收集独立样本再评估。

本轮确定完成的是金额异常提示、失败模板识别、复核记录与对照分析能力。尚未解决的主要任务仍是可见金额的数字和标签对应；本轮没有训练或微调模型。

### 对照与留出样本

`evaluate.py --offset` 支持跳过已用于开发的样本，保持原数据指纹并记录选中的 ID。对比报告同时展示每个字段从错误变正确和从正确变错误的次数。

本轮固定：NF4 权重、BF16 计算、同一模型版本、同一图片与像素范围、同一生成上限、同一评测源代码；只切换提取规则。

这里的提取规则包括系统提示与输出形状。不同开发阶段的源代码不同，长规则尝试和简洁规则尝试不作为同源代码的一次对照；每个阶段都重新运行 baseline。

1. 在已使用的前 20 张上运行两种规则，检查修正和退步。
2. 冻结规则，再用剩余 80 张验证票据运行两种规则。这是本轮留出验证，不能称为新的官方测试成绩。
3. 后续若再根据这 80 张修改规则，需要另收集独立标注票据再评测。

原 2026-10-03 测试报告继续对应原来的代码和 baseline 提示，不用本轮验证结果替换原测试成绩。

## 在已有 AutoDL 实例运行

在模型和官方数据缓存已验证的环境中，激活原虚拟环境并设置 `HF_HOME=/root/autodl-tmp/receipt-cache/huggingface`。该脚本只读取缓存；不会重新下载模型。

如果上一轮完整数据位于 `validation-final`：

```bash
export RECEIPT_DATASET=data/cord/validation-final/annotations.jsonl
bash scripts/run_receipt_improvement.sh pilot
```

检查 `artifacts/runs/receipt-labels-pilot-时间戳/comparison.md` 和两组 `errors.csv` 后，冻结方案再运行：

```bash
bash scripts/run_receipt_improvement.sh holdout
```

标准导出路径可不设置 `RECEIPT_DATASET`。脚本核对完整验证集、固定的数据版本与任务定义，并创建新的输出目录。两种规则均会记录真实原始输出和完整运行配置。

默认候选为 `label-context-v1`。设置 `RECEIPT_CANDIDATE` 可复跑其他开发实验：`label-aware-v1`、`receipt-compact-v1`、`amount-recheck-v1`、`percent-crop-v1`。直接使用最终候选时设置 `MLLM_RECEIPT_PROFILE=baseline`、`MLLM_RECEIPT_RECHECK=label-context-v1`。

保存并下载结果后，在云平台停止实例。脚本不会自动关闭付费机器。
